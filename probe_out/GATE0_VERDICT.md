## Ответ: ЗЕЛЁНЫЙ СВЕТ для бесплатного слоя

Твой обычный аккаунт **видит реальные Telegram-хендлы** у бесплатных публикаций.

### Как устроено на самом деле

1. **Авторизация — не кука, а Bearer-токен.** SPA держит `access_token` в
   `localStorage`, шлёт заголовком `Authorization: Bearer <token>`. Куки в
   авторизации не участвуют (cookieLen = 0). Первый парный диф дал ложное
   совпадение, потому что fetch с куками = анонимный запрос.

2. **`mode` вакансии определяет доступ:**
   - `mode: "full"` → все ссылки раскрыты, включая `telegram: https://t.me/...`
   - `mode: "preview"` → все ссылки `"#"` (это VIP-публикации, их paywall)

3. **Это свойство вакансии, не квота.** Перечитывал `full` и `preview` по 3
   раза — стабильно. Полей `views_left`/`unlock`/`quota` в ответе нет. Значит
   лимита на просмотры нет: бесплатные открыты всегда, VIP закрыты всегда.

4. **Пропорция:** на выборке 40 вакансий — **23 full / 17 preview** (~57%).
   Из 250 в целевой ленте это ~140 вакансий с готовыми контактами.

### Проверенные факты API

| Что | Значение |
|---|---|
| Список | `GET /api/jobs?links_type=all&links=telegram&remote=true&offset=N`, total=250 |
| Деталь | `GET /api/jobs/{uuid}` — поля: id, kind, tag, content, features, links, offers, mode, posted_at |
| Авторизация | `Authorization: Bearer <access_token из localStorage>` |
| `/api/users/me` | под Bearer отдаёт `{id, mail, access_token}` |
| Пул под Сурена | product manager 9, product 73, backend 49, python 63 |
| Формат хендла | `links[i] = {key:"telegram", value:"https://t.me/<handle>"}` |

### Границы (соблюдаем)

- `preview`-вакансии (VIP) **не трогаем** — обходить их paywall запрещено.
  В пайплайне помечаем `HANDLE_MISSING`, пропускаем.
- Работаем только с `mode:"full"`.

### Следствие для архитектуры

Полный пайплайн строим как в плане, §3 (анти-бан) остаётся в силе:
холодные DM в Telegram по ~140 бесплатным вакансиям, рампа 3→15/день.
