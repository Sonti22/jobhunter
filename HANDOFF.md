## Что это за проект

`jobhunter` — локальная система поиска работы для владельца (Суреn Акопян,
Python/Backend/Tech Lead, 7 лет). Собирает вакансии, пишет персональные
отклики с проверкой на выдумки, рассылает в Telegram и на email, ведёт
переписку с рекрутёрами, согласует интервью с владельцем и пишет их в Google
Calendar.

Работает в Docker на машине владельца: контейнеры `autopilot` (сбор,
отправка, переписка), `bot` (пульт @MyJobbb_bot), `web` (дашборд
`127.0.0.1:8765`), плюс one-shot `migrate`.

## Что делать дальше

**Этап 3 — очередь ручных откликов.** 4111 вакансий без прямого контакта
лежат мёртвым грузом: отклик через форму компании, но нет ни очереди, ни
отметки «откликнулся», ни напоминаний. Владелец выбрал оба интерфейса:
утренняя пачка в боте и полный список на дашборде, отметки общие.

Ключевые решения, уже принятые (не пересматривать без причины):

- Состояние отклика — в поле `Application.outcome`, а **не в статусе**.
  Поле свободно (проверено grep'ом). У `HANDLE_MISSING` в графе переходов
  всего два выхода, и втаскивать ручные отклики в машину состояний значит
  переписывать граф и ломать смысл воронки, где «отправлено» = «система
  отправила сама». Значения: пусто, `applied`, `not_fit`, `snoozed`.
  Плюс новые колонки `applied_at`, `snooze_until`.
- `manual_apply.listing()` сейчас фильтрует `Job.source LIKE 'ats:%'` — из
  4111 показывает только ATS. Расширить.
- `rescore_all()` не идемпотентна: берёт `score == 0.0` и обнуляет
  нерекомендованные, поэтому каждый прогон пересчитывает те же строки.
- Утренняя пачка — обычные уведомления `notify.push` с клавиатурой, а не
  `OwnerRequest`: решение здесь ничего не отправляет, исполнять автопилоту
  нечего.

**Этапы 4 и 5** — бот (показ письма перед отправкой, ручной запуск шагов,
утренний дайджест) и аналитика откликов. Подробности в плане.

**Заявки, забракованные самопроверкой,** копятся в `PENDING_APPROVAL` с
непустым `Application.review_note` и не идут в автоотправку. Показать их
владельцу с кнопками «отправить как есть / переписать / пропустить» — часть
этапа 4; пока их видно только на дашборде.

## Грабли, на которые уже наступали

Каждая стоила времени. Не наступать снова.

**Heredoc в Bash съедает обратные слеши.** `cat > file <<'EOF'` с `\n` внутри
Python-строк превращает их в реальные переносы и ломает файл. Для кода с
экранированием использовать Write/Edit, не heredoc.

**Изменения кода не видны контейнеру без пересборки.** Код запечён в образ
(`COPY jobhunter/`). После правки: `docker compose build migrate && docker
compose up -d`. Забывается регулярно и выглядит как «правка не сработала».

**Новая колонка в модели не появляется в рабочей базе.** Нужна запись в
`db.py::_ADDED_COLUMNS`, иначе поле есть только на пустой БД. На это уже
наступили; теперь есть `tests/test_schema_migrations.py`, который падает при
расхождении. Индексы — отдельным списком `_ADDED_INDEXES`.

**Пути в БД переживают переезд, файлы — нет.** `cv_path` хранился
windows-путём, невидимым из контейнера, и резюме молча не прикладывалось к
отклику. Лечится `tailor/render.py::resolve_cv()` — вызывать его перед любой
отправкой файла, а не доверять `Path(cv_path).exists()`.

**Тесты уходили в сеть.** Автоответ на входящее письмо честно подключался к
`smtp.gmail.com` с таймаутом 30 секунд — набор зависал. В почтовых тестах
есть autouse-фикстура `no_smtp`, она же глушит человеческую паузу
`reply_delay_seconds` (40–480 секунд в бою).

**Состояние течёт между тестами.** Модульная фикстура БД + водяной знак IMAP:
первый тест продвигал знак до uid 1099, и письма следующего теста считались
прочитанными. В `test_mail_inbox.py` есть `clean_apps`, чистит и таблицы, и
знак. Порядок удаления важен из-за внешних ключей.

**Письмо без объявленной кодировки.** Разбирается как us-ascii, кириллица
превращается в символы замены, маркеры цитат не находятся — и время из
цитаты доезжает до классификатора. В `imapbox.fetch_body` есть запасное
декодирование utf-8/cp1251/koi8-r.

## Архитектурные границы, которые нельзя нарушать

**Бот не отправляет рекрутёрам.** Писать может только процесс, владеющий
`jobhunter.session` (автопилот). Бот кладёт решение в `owner_requests`,
автопилот исполняет раз в 5 минут. Запрет закреплён тестом
`test_bot_never_imports_telethon`.

**Один Telethon-клиент на сессию.** Все MTProto-шаги автопилота идут через
`ThreadPoolExecutor(1)` с `executor="tg"`. Два клиента = `AuthKeyDuplicatedError`
и разлогин аккаунта. С хоста `python -m jobhunter...` при живых контейнерах
не запускать — только `docker compose exec autopilot ...`.

**Почта читается, но не хранится.** Проход двухфазный: заголовки всех писем,
тело — только для привязанных к заявке. Ящик открывается `readonly=True` с
`BODY.PEEK`, флаги не меняются. Тесты проверяют оба свойства.

**Гейт против выдумок.** Любой текст от LLM сверяется с `profile.yaml`:
техтермины, цифры, годы. Не прошло — берётся шаблон. Обходить нельзя.

**Очистка цитат — вопрос корректности.** Без неё наш же автоответ со слотами,
процитированный в ответе рекрутёра, читается как предложение времени, и бот
подтверждает живому человеку интервью, которого не было. Тест
`test_quoted_slots_do_not_leak_to_classifier`.
