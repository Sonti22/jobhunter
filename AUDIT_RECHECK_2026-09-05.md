## Что исправлять дальше

### 1. Высокий приоритет: секреты и личные данные отслеживаются Git

`git ls-files` включает `google_token.json`, `google_client_secret.json`, `jobhunter.db.moved` и её WAL/SHM, а также архивы переписки `logs/sent/`.

В JSON действительно присутствуют непустые поля токена, refresh_token и client_secret; их значения не выводились. Видимость удалённого репозитория и доступность этих данных посторонним не проверялись. В текущем Docker-образе перечисленные секретные файлы и архивы бэкапов не обнаружены: Dockerfile копирует выбранные каталоги, а не весь проект.

Следующий шаг: добавить исключения и убрать чувствительные файлы из индекса с сохранением локальных копий. Уже попавшие в историю секреты этим не исчезнут: отдельно проверить, куда отправлялась история, и при необходимости отозвать/заменить токены. Переписывание истории и отзыв доступа требуют отдельного решения владельца.

### 2. Средний приоритет: штатная проверка резервной копии не работает в Windows PowerShell

Воспроизведено командой `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/verify_backup.ps1`.

Результат: код 1, вложенный `sh` завершается с `Syntax error: end of file unexpected (expecting "fi")`. Сообщение скрипта о невосстановимости бэкапа в этом случае неверно: до проверки SQLite он не дошёл. Место: `scripts/verify_backup.ps1`, передача многострочного shell-кода начиная со строки 17.

Последний архив `backup/jobhunter-data-20260905_151326-pre-dashboard.tgz` проверен независимым способом: база и WAL/SHM извлечены во временный каталог, `integrity_check: ok`, **10 615 заявок**. Рабочая база не заменялась. Проверена именно база в архиве, не полный запуск восстановленного приложения.

### 3. Средний приоритет: обычный backup_volume.ps1 не гарантирует согласованный снимок

Скрипт выполняет WAL-checkpoint, затем архивирует живой том, не останавливая писателей. Между этими действиями автопилот может изменить базу и WAL. Кроме того, наличие файла архива принимается за успех без обязательной проверки результата tar и восстановимости перед ротацией.

Это риск реализации, а не доказанное повреждение последней копии. Следующий шаг: SQLite backup API для согласованной копии либо согласованная остановка всех писателей на время полного снимка; затем проверка копии до удаления старых архивов. Место: `scripts/backup_volume.ps1`, строки 23–44.
