# Безопасность, правила площадок и закон

Бот пишет людям от вашего имени. Это удобно, но ответственность за каждое
сообщение — ваша. Здесь собрано то, что нужно знать до включения отправки.

> Этот документ — не юридическая консультация. Если сомневаетесь, как закон
> вашей страны относится к рассылке и хранению контактов, спросите юриста.

## Telegram: главный риск — ваш аккаунт

Бот может работать через ваш **личный** Telegram-аккаунт (шаг 10 установки).
Telegram ограничивает аккаунты, которые пишут первыми незнакомым людям, если
получатели жалуются. Ограничение («ваш аккаунт ограничен», @SpamBot) означает:
писать тем, кого нет в контактах, нельзя неделями; снимается только по сроку.

Это не теория. Аккаунт автора проекта получил ограничение на четыре недели:
несколько сигналов антиспама (PeerFlood) подряд, затем жалобы получателей,
подтверждённые модераторами. Аккуратный темп не спас: жалоба — это решение
человека, а не частота сообщений.

Поэтому:

- **Холодная рассылка выключена по умолчанию** (`TELEGRAM_COLD_ENABLED=false`).
  Бот готовит такие отклики, а отправляете вы сами через `/outreach`: один
  клик открывает чат с готовым текстом.
- Ответы тем, кто **написал вам первым**, работают всегда — это обычная
  переписка.
- Если вы всё же включаете холодную рассылку:
  - не чаще одного нового адресата в 30 минут, только днём по времени получателя;
  - один контакт на работодателя раз в 30 дней;
  - первый PeerFlood — отправка встаёт на двое суток, второй — навсегда в
    ручной режим;
  - каждое утро бот спрашивает @SpamBot о состоянии аккаунта и сам
    останавливается, если аккаунт ограничен, а после снятия — сам возобновляет;
  - пишите только туда, где рекрутёр **сам опубликовал** свой контакт для
    откликов.
- Не используйте для этого основной аккаунт, если он вам дорог.

**Чтение каналов.** Публичные каналы бот читает через веб-превью `t.me/s/…`,
как обычный посетитель: браузерный User-Agent, не чаще запроса в 2 секунды,
сохраняются только посты с вакансиями. У Telegram нет `robots.txt` для этих
страниц, но условия лицензирования контента запрещают массовый сбор
(scraping, harvesting). Риск небольшой, но ненулевой — решение за вами;
выключить можно, очистив список каналов.

**Сессия** (`jobhunter.session`) — это полный доступ к аккаунту. Никогда не
публикуйте её и не запускайте два клиента с одной сессией (разлогинит).

## Почта

- **Прогрев.** Новый ящик, который сразу шлёт сотни писем, Gmail ограничит.
  Бот начинает с 40 писем в день и прибавляет по 5 за каждый день без
  отбивок до `EMAIL_DAILY_LIMIT` (80). Личный Gmail допускает до 500
  получателей в сутки, но с вложениями и холодными письмами безопасный
  потолок гораздо ниже.
- **Отбивки.** Несколько отбивок подряд останавливают отправку: отбивки
  портят репутацию ящика.
- **Только опубликованные адреса.** Бот пишет на адреса из текста вакансии,
  с сайта компании, из публичного профиля GitHub или поста автора. Каждый
  адрес хранит ссылку на источник. Адреса не угадываются (`имя.фамилия@`), не
  проверяются на почтовом сервере, не покупаются.
- **Отказ от писем.** Прямые письма руководителям заканчиваются строкой «если
  не по адресу — ответьте „нет“, больше не напишу». Любой ответ останавливает
  автоматические напоминания по этой заявке, а отбивка сама помечает адрес
  «не писать». Если человек просит больше не писать — внесите компанию в
  blacklist (панель → `/blacklist`): бот не будет писать ей никогда.
- **Повторные контакты.** Одному работодателю бот пишет не чаще раза в 30 дней.

## Персональные данные

В базе бота оказываются контакты и переписка рекрутёров. С точки зрения
закона это обработка персональных данных:

- **Россия — 152-ФЗ «О персональных данных».** Контакт, который человек сам
  опубликовал для откликов, вы используете по назначению — для отклика. Не
  передавайте базу третьим лицам, не используйте контакты для другого, по
  просьбе человека удалите его данные.
- **ЕС — GDPR**, если пишете европейским компаниям: основание — законный
  интерес (вы откликаетесь на опубликованную вакансию), у человека должно
  быть право отказаться и потребовать удаления.
- **США — CAN-SPAM** касается коммерческих писем; отклик на вакансию к ним
  обычно не относится, но честная подпись и возможность отказаться всё равно
  нужны.

Практически:

- данные хранятся только у вас — в томе Docker и в папке `out/`;
- тексты, которые уходят в нейросети, очищаются от телефонов и адресов
  (`LLM_REDACT_PII=true`);
- компанию, которой больше нельзя писать, внесите в blacklist (панель →
  `/blacklist`);
- **никогда не публикуйте** базу, резервные копии и `out/logs/`: там чужая
  переписка.

## Правила площадок

Источники подключались с проверкой `robots.txt` и условий использования
на момент подключения (август–сентябрь 2026). Правила меняются — проверяйте
сами и выключайте лишнее через `DISABLED_SOURCES`.

Намеренно **не подключено**:

| Что | Почему |
|---|---|
| hh.ru | API для соискателей закрыт (декабрь 2025), браузерные «автокликеры» нарушают правила и ведут к бану |
| LinkedIn, Wellfound, сайты за логином | запрет правилами; автоматизация аккаунта — бан |
| Автозаполнение форм ATS браузером, обход CAPTCHA | отсеивающие вопросы заполняются неверно и закрывают компанию навсегда |
| Покупные базы контактов (Apollo, Hunter и т. п.) | данные собраны без согласия людей |
| Пиксели открытий и отслеживание кликов | бьют по доставляемости и приватности получателей |

Ashby — исключение из правила про формы: отклик подаётся через документированный
публичный API самой Ashby и только если каждое обязательное поле заполняется
фактами из вашего профиля.

## Правда о вас

Гейт правды не даёт боту **приписать** вам то, чего нет в профиле. Но он
доверяет самому профилю: если вы впишете туда навык, которого у вас нет, бот
честно о нём напишет. Ответственность за профиль — ваша. Уровень `familiar`
существует ровно для того, чтобы не завышать.

## Секреты

Эти файлы дают доступ к вашим аккаунтам и данным. Все они в `.gitignore` и
`.dockerignore`; проверка `python -m jobhunter.repo_safety` в CI не даст
закоммитить их по имени.

| Файл | Что даёт |
|---|---|
| `.env` | токен бота, ключи API, пароль приложения Gmail |
| `profile.yaml`, `cv_base/` | ваши контакты и вся карьера |
| `jobhunter.session` | полный доступ к Telegram-аккаунту |
| `google_token.json` | чтение и отправка вашей почты, календарь |
| `google_client_secret.json` | ключ вашего проекта Google |
| `tg_code.txt`, `tg_2fa.txt` | код входа и облачный пароль (удаляются сами) |
| `backup/*.tgz` | база, сессия и токены целиком |
| `out/logs/` | переписка с рекрутёрами |

**Если секрет утёк** (например, попал в публичный репозиторий):

- Telegram-сессия: Telegram → Настройки → Устройства → завершить сеанс, затем
  войти заново (`tg_login.py`);
- токен бота: @BotFather → `/revoke`, новый токен — в `.env`;
- Google: [myaccount.google.com/permissions](https://myaccount.google.com/permissions)
  → удалить доступ приложения; в Cloud Console сбросить секрет OAuth-клиента;
  войти заново (`googleauth --login`);
- ключи нейросетей и GitHub — перевыпустить в их консолях;
- пароль приложения Gmail — удалить и создать новый.

Удаление файла из репозитория **не удаляет его из истории git**: он остаётся
в прошлых коммитах. Отзовите секрет в любом случае — боты находят утёкшие
ключи на GitHub за минуты.
