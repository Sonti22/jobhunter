# Как устроен код

## Процессы

Четыре сервиса Docker на одном образе (`docker-compose.yml`):

```
            ┌───────────── том jobhunter-data ─────────────┐
            │  jobhunter.db (SQLite, WAL)  jobhunter.session │
            │  google_token.json   STOP_SENDING.flag         │
            └──────┬──────────────────┬──────────────┬───────┘
                   │                  │              │
  migrate ──► autopilot          bot (пульт)     web (панель)
  схема БД    расписание:        Telegram Bot    127.0.0.1:8765
  и выход     сбор → отбор →     API: экраны,    очередь, история,
              письма → отправка  кнопки,         причины ожидания,
              → переписка        уведомления     стоп-кран
```

- **Единственный владелец Telegram-сессии — `autopilot`.** Бот-пульт и
  панель не пишут в Telegram от вашего имени: решения (кнопки) кладутся в
  очередь в базе, автопилот исполняет их в течение пяти минут.
- База — SQLite в томе Docker: на смонтированной папке Windows файловые
  блокировки ненадёжны. Всё, что открывается глазами, — в `./out`.
- Планировщик — APScheduler с тремя пулами: общий, `tg` (один поток — всё,
  что открывает Telethon, строго последовательно) и `beat` (пульс для
  healthcheck). Пропущенные из-за сна компьютера шаги догоняются после
  пробуждения; дневные задания защищены маркерами «сегодня уже выполнено».
- Сторож: если пульс Telegram-пула не обновлялся час, процесс завершается, и
  Docker его перезапускает.

## Конвейер заявки

Заявка (`Application`) проходит статусы (`jobhunter/models.py → Status`):

```
DISCOVERED ─► SCORED ─► CONTENT_READY ─► PENDING_APPROVAL ─► APPROVED ─► SENDING ─► SENT
   │            │            │                                                    │
   │            ▼            ▼                                                    ▼
   │     REJECTED_SCORE  GATE_FAILED                                       AWAITING_REPLY
   ▼                                                                      │     │
DUPLICATE, HANDLE_MISSING (нет контакта → ручная очередь)       FOLLOWED_UP   REPLIED
                                                                      │     │
                                                          NO_REPLY_CLOSED   IN_DIALOGUE ─► NEEDS_HUMAN
                                                                                  │
                                            INTERVIEW_PROPOSED ─► INTERVIEW_CONFIRMED ─► INTERVIEW_DONE ─► OFFER
                                            REJECTED_BY_EMPLOYER, WITHDRAWN, SEND_FAILED(_AMBIGUOUS), HANDLE_DEAD
```

- Переходы — только через `Application.transition()`/`advance()`: в
  `PENDING_APPROVAL` нельзя попасть, не пройдя гейт.
- `SENDING` фиксируется **до** сетевого запроса вместе с ключом
  идемпотентности. Упал процесс посреди отправки — заявка уходит в
  `SEND_FAILED_AMBIGUOUS` и не отправляется повторно вслепую.
- `REJECTED_SCORE` — конечный статус.

## Гейт правды

`jobhunter/tailor/gate.py` проверяет каждое резюме и письмо перед очередью:

1. **провенанс** — каждый пункт резюме восходит к записи профиля (похожесть ≥ 0,6);
2. **числа** — каждая цифра подтверждена метрикой, датой или стажем;
3. **технологии** — только из профиля; `never_claim` и `level: none` запрещены везде;
4. **утечка терминов вакансии** — что всплыло из её текста, помечается (`promoted_terms`);
5. **стаж** — заявленные годы сходятся с опытом, стаж по навыку не завышен;
6. **компании** — только из вашего опыта;
7. **уровень** — навык уровня `familiar` нельзя в заголовок и рядом с «экспертный».

Любое нарушение — `GATE_FAILED`, отправка невозможна. Тексты нейросети
проходят тот же гейт, плюс самопроверку читаемости и проверку позиций
кандидата (переезд, формат работы, `outreach.never_say`).

## Тексты о кандидате

Всё, что бот говорит о вас от первого лица, — в `profile.yaml → outreach`,
читается через `jobhunter/persona.py`. В коде нет имени, города, стажа и
формата работы конкретного человека; без раздела `outreach` бот собирает
нейтральные фразы из `identity` и `claims`.

## Тесты

```bash
python -m pytest tests/ -q
```

- ~1400 тестов, офлайн: `tests/conftest.py` запрещает сеть, выключает
  нейросети и подменяет пути к артефактам.
- Работают на вымышленном `profile.example.yaml`.
- `tests/test_profile_real.py` проверяет ваш настоящий `profile.yaml`, если он есть.
- CI (`.github/workflows/ci.yml`): `repo_safety`, `ruff`, `mypy` по ядру,
  `pytest` с покрытием ≥ 50 %, `pip-audit`.
